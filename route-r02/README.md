# 入山 R02：把可见边缘交还给笔墨

R02 沿用 R01 固定游线，新增原墨迹外缘和独立的内部覆盖。

## 使用

打开 `SHUIMO_ROUTE_R02.html`。它是自包含 HTML，没有 CDN、外部图片或模型请求。推荐启用 WebGL 的桌面浏览器。默认无雾、左右对照：左侧固定旧裁切，右侧是新的墨迹边缘。

右侧可以切换三种边缘表示：

- **手工山形裁切（旧逻辑）**：保留原来手工 alpha 的对照；使用本轮一致的透明合成管线，不是旧版整套渲染的逐像素复刻。
- **仅羽化旧边界**：同一轮廓做均匀羽化；不恢复已经裁掉的原墨迹。
- **原墨迹外缘 + 内部遮挡**：原墨层与内部覆盖分开合成，墨迹可以出现在原裁切线外。

可以单看主峰、切换洋红诊断底色，或查看内部覆盖 C、墨层 I、最终透明度 α。字段视图自动只显示主峰；白表示字段数值大，不代表最终画面里的白纸。显示托底网格会看到覆盖透明余量的矩形支架，它不是可见山形。

沿用前进、暂停、倒退、路线拖动和有限转头。画面拖动可改变视角；空格开始/暂停，上下键迈步。本轮不做近景或全景绕行。

## 本轮修改

R01 的承载网格原本就是矩形；外观被资产编译器的手工 `CONTOURS` 覆盖遮罩裁成了山形。问题不需要用三维墨雾解决，而是需要取消这一可见裁刀。

R02 托底的 UV 域扩大为 `[-0.10, 1.10] × [-0.05, 1.05]`，即左右各增加原宽度的 10%、上下各增加原高度的 5%。原画的世界坐标不随之放大。新增面积是透明支撑余量，不是新的可见山体，也不是从旧图凭空补出来的笔触。

拆开两个字段：

- `I`：此旧图适配器的墨层不透明度，由纸底归一化后的缓存墨迹近似得到；不是深度。
- `C`：山内纸白表面的覆盖。内部留白仍然能遮挡后山；它不因“没墨”就变成洞。

本轮固定墨色的合成是：

```
alpha = I + (1 - I) * C
premultiplied_rgb = ink_rgb * I + paper_rgb * (1 - I) * C
out = premultiplied_rgb + background * (1 - alpha)
```

外缘 C 逐渐降为 0 后，已有墨迹仍可单独存在；外圈 I、C 都为 0，托底不可见。山内 C=1，即使 I=0，仍是不透明留白。这是一个绘画景片合成约定，不是三维墨扩散或完整光学输运模型。

纹理在上传时预乘，再生成 mipmap；使用 `ONE, ONE_MINUS_SRC_ALPHA` 合成，不再用 0.02 的 alpha 阈值切掉淡墨。山体和雾统一按既定深度层排序，透明景片不写深度。本场景的山体/雾片深度层没有相交；此方式不承诺解决任意交叉透明几何。

## 与未来笔触模块的边界

**这轮没有重写笔触，也没有真正接入另一路笔触引擎。** 使用的仍是已有低分辨率山体 PNG。没有笔触级墨色、透明度和表面覆盖，因此临时适配器通过图像支持区域、闭合和孔洞填充估计 C，并使 C 在外围向里退让。

中央主峰及其远景复用（T05）不再使用旧手工轮廓来生成新模式的 alpha。其他几张旧画包含无关笔迹，使用扩松且渐退的语义区域排除远离主体的碎片；这个区域不是逐像素的可见山形。本轮没有声称从 RGB 图片自动恢复了准确的山体语义。

这种估计可能误填外部缝隙、遗漏开口留白；旧缓存也仍然模糊。后续正确接线是：由绘画模块直接输出同一坐标系里的墨层、内部覆盖和有效画幅。本轮不继续堆分割补丁来替代该接口。详见 `BRUSH_ADAPTER_CONTRACT.md`。

## 复现与恢复

运行时只需 HTML。重建资产需要 Python、NumPy、SciPy 和 Pillow；浏览器回归另需 Playwright、Chromium。依赖以实际测试环境为准。

```
python -m pip install -r requirements-tested.txt
python -m playwright install chromium
python -X utf8 src/build_assets.py
python -X utf8 src/build.py
python -X utf8 src/test_browser.py
```

可用 `CHROMIUM_EXECUTABLE` 指定本机 Chromium。Linux 容器若直接无显示运行超时，可在测试命令前加 `xvfb-run -a`。测试将 HTML 注入浏览器，结果写入本地 `evidence/`。

`scene_r01.json`、`baseline_assets/` 中的山形贴图和 `frozen_cache/` 中的墨画是离线重建输入。

## 范围

没有新增三维墨烟、自动新视点绘画、笔触物理求解、自由漫游、双目 VR 或近景。演示仍采用手工路线、粗深度和已有局部 A/B 缓存。程序测试通过不等于视觉质量、人眼阈值或帧率认证。
