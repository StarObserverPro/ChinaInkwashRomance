# 水墨固定游线中远景引擎 — R1 设计稿

状态：架构提案，尚未实现、未完成视觉测试或性能实测。
范围：冻结现有笔触方案；仅讨论中远景绘制、复用、换景及云雾协调。极近景的投影方式不在本轮设计范围内。

## 1. 引擎定义

以固定游线为约束，预先或低频生成高质量水墨景片；运行时只进行轻量投影、可见性处理和合成。

不是低帧率重画整个视野，也不是实时把普通三维山体套水墨滤镜，而是“空间关系连续，水墨画法分段更新”的游线布景系统。

初版假设：单目屏幕体验，路线位置受约束，可以停步、倒退和在约定范围内转头。固定路线不等于固定朝向；镜头位置用路线弧长 s 参数化，额外记录朝向、视场角和允许的横向偏移。全自由六自由度、双目显示与近景互动都不是初版承诺。

若连相机朝向与运动时序也完全固定，预渲染影片应作为成本基线；本方案额外提供的价值是变速、停步、倒退、小幅转头以及局部复用。

## 2. 空间骨架与画面自由度

用极粗的几何和山脊关系定义空间骨架：峰的位置、山脊转折、前后遮挡、山谷方向、层级深度。几何是投影和校验依据，不是最终美术表面。

优先稳定：主峰轮廓、山脊交点、谷口、前后山交界，以及少量识别性地标。

允许更大简化：雾中的山脚、弱皴区域、远坡、留白边界。艺术调整在离线阶段通过统一的空间约束进行，不允许运行时随意移动山峰去追逐相机。

可在场景创作时将某座山推远并同比放大，维持角尺寸、降低侧向视差。这是固定的布景设计，不是随镜头逐帧变化的补丁。中景、远景最终按视差和可复用范围分类，不以固定米数切分。

## 3. 景片不是普通始终朝向相机的公告板

### 3.1 分层表示

- 极远天际线：宽幅画带、弧面或分方向背景；只覆盖已承诺的观察域。
- 远山群：独立山体卡片或少量深度分层，允许不同层有不同视差。
- 中景主山：低分辨率起伏网格，或按山脊、坡面拆分的深度景片。
- 山间雾与谷雾：世界空间中的薄片组或轻量密度场，独立于山体绘画。

不能把有明确前后关系的所有山画在同一张平板上，也不应让整座山始终旋转着朝向相机。中景景片需有固定场景坐标；只有在已验证的游线区间内允许有限形变。

### 3.2 InkPatch 资产契约

每个景片至少携带：

| 字段 | 用途 |
| --- | --- |
| patch_id / mountain_id / version | 稳定身份和可追溯版本 |
| reference_camera | 生成时的投影条件 |
| proxy_mesh 或 depth | 当前镜头下的重投影 |
| pigment / appearance | 水墨画迹或可合成外观 |
| surface_coverage | 山体表面的覆盖关系，不能从墨色直接推断 |
| silhouette / ridge / region_id | 轮廓约束、山脊对应与语义分区 |
| stroke_plan / stroke_id（条件允许时） | 保留旧笔迹身份，局部重画而不是整张重新随机生成 |
| valid_view_domain | 可使用的路线、朝向和偏移范围 |
| hidden_region / overscan | 转弯后露出的后层和画面边缘余量 |
| style_scale / tone_signature | 尺度和墨色层级检查 |
| checksum / dependency_versions | 缓存及恢复校验 |

这是一份新增接口建议，不表示旧笔触输出已经含有以上所有字段。缺失的深度、覆盖和语义字段先由简单几何或手工标注补充；不要求先建设通用的自动三维重建器。

山体留白仍然属于山体。皴笔之间的白不应该自动透出后山；必须分开“表面覆盖”与“墨色浓淡”。纸底可在合成端统一，但轮廓外的空白才真正作为背景空域。边缘晕染单独保留软边，不用一个粗糙阈值抠掉。

深度也不能从墨色直接推断。浓淡是艺术属性，不是可靠的几何深度。

## 4. 两个速度的系统

```text
游线 + 视域 + 山体骨架 + 构图约束
                  ↓
           游线与可见性编译器
                  ↓
   参考视点 / 分层 / 有效域 / 隐藏面 / 换景窗口
                  ↓
        现有笔触绘制器（离线或低频）
                  ↓
          景片缓存与版本清单
                  ↓
运行时：镜头更新 → 选景片 → 重投影 → 遮挡 → 雾 → 合成
```

慢速部分负责真正的落笔和纸墨求解；快速部分不重新模拟整幅画的毛笔接触与纸内输运。

固定路线使必要资产可以预生成。初版应优先完成所有承诺观察域的覆盖；按需绘制是后续优化，而不是正常行走过程中必须等待的外部依赖。

运行时缓存保留当前区段和前后区段。停步不得触发随机重画，倒退不得每次重新抽取笔法或丢掉刚看过的山。

## 5. 自适应游线采样与有效观察域

先密集采样便宜的代理几何，而不是密集调用昂贵的笔触绘制器。先放少量参考视点，测试其在邻近路线和约定转头范围内的投影、覆盖与笔迹变形，再在失效区间增添参考视点。

每一组景片都有一个有效观察域，而不只是一个生成点。相邻观察域必须重叠；转弯、遮挡拓扑变化、画面边缘露出新内容的地方，需要更密的采样或增加独立后层。

路线切分按每个山体独立进行。近一些的山可以更新多次，而远山一直复用；不把所有层绑成一张整屏关键帧。

对允许的转头做显式覆盖测试。单张前向平面图像不能支持未经覆盖的回头视野；需要更宽画幅、其他方向景片或全景层。镜头旋转本身不必重画笔触，但旋转后新进入视野的内容必须存在。

## 6. 复用预算：判断误差，而不是判断画面移动了多少

对纯横向小位移，以单平面深度 Z0 代替真实/代理点深度 Z 时，像素投影残差近似为：

    e_px ≈ f_px × |Δx| × |1/Z - 1/Z0|

    f_px = W / (2 tan(FOVx/2))

这是针孔投影下的局部几何估算，不是实测的感知阈值。转弯、前进、俯仰、轮廓显露等情况用完整代理几何和投影检查，不直接套此公式。

示例设定：屏宽1920像素，水平视场角60度，横向移动2米。焦距约 1662.77 像素。

| 示例 | 深度范围 | 代表平面深度 | 最大残差 |
| --- | --- | --- | --- |
| 中景 | 200–500 m | 300 m | 5.54 px |
| 远景 | 1500–3000 m | 2000 m | 0.55 px |

同样的步长对远山可能足够小，对中景却需要更细的分层或起伏网格。实际画面移动十几像素不表示出错；需要限制的是廉价表示相对目标空间关系的残差。

分开检查以下误差，不用一个全屏均值掩盖局部大错：主轮廓残差、笔迹拉伸/剪切、新露出但没有内容的区域、笔触尺度失配、相邻版本墨色及结构差异。

概念性的景片风险值：

    E_j = max(e_ridge/τ_ridge,
              e_warp/τ_warp,
              e_hole/τ_hole,
              e_scale/τ_scale,
              e_tone/τ_tone)

各量先分别归一化。主峰与无遮挡破洞属于硬门槛；弱皴、低对比雾区可使用更宽的局部预算。优先比较相邻版本在同一目标镜头下的结果，而不是直接比较两张不同参考视点图片。

## 7. 重绘是同一座山的新观察版本

相邻版本必须共享山体身份、结构地标、区域划分、笔法类别及墨色基调。可复用笔迹优先重投影，变化区域局部重画，未曾可见的区域补画。

固定随机种子只能辅助重复性；它不保证从两个视点画出的笔迹有几何对应。关键是明确笔迹或区域的稳定身份，以及它在场景骨架上的位置。

建议区分三类画迹：

- 轮廓与主山脊：以共享几何或共同地标严格对齐。
- 皴擦纹理：附着于对应坡面，受控变形，在适当窗口局部替换。
- 淡染与气氛：对齐大范围浓淡结构，允许更柔和的过渡。

更换景片不能只做两张整图的透明度交叉渐变。先把新旧版本投影到同一当前视点，检查轮廓/山脊是否对应；不对应的强边缘不能同时半透明出现。先解决结构再混合弱纹理和淡染。

轮廓应保持单一、稳定的结构来源。不能对齐的中景结构应该增设中间参考版本，或在真实遮挡下整块交接，而不是让两个山峰暂时重影。

几何覆盖正确不代表所有纹理都能无限拉伸。需要把画迹变形和尺度质量作为独立失效条件。

## 8. 尺度、纸感与笔触模块接口

区分世界空间尺度、参考画面/画纸尺度和当前屏幕尺度。前两者属于资产创作条件，屏幕尺度由当前投影决定。

初版尽可能复用现有笔迹；当放大、缩小或斜视超出允许范围时，使用预生成的另一档画迹，而不是在运行时篡改毛笔物理参数。

不同档位保留同一组主要轮廓和皴理关系；远处可减少细笔，近一些可补细部，但不能突然换一套结构。缩小图像只是采样降级，不等于完成了适当的用笔尺度设计。

墨迹边缘的纸墨细节跟随画迹；统一纸底保持很弱，不能成为静止的强屏幕噪声。初版不新增复杂的动态纸纹研究分支。

## 9. 云雾作为布景构成，而不是错误开关

谷雾切断对山脚连续几何的要求，坡间雾形成深度间隔，靠近观众的薄雾缓解进入未来近景系统之前的过渡。

雾应有连续的场景位置和缓慢运动，不能每帧独立随机生成形状，也不应与相机完全同步平移成屏幕贴纸。可先用几组水墨云雾薄片和低频运动，不必完整实现体积流体。

设计时建立路线上的雾带和留白区，让它们自然提供一些景片交接窗口。但“该换图了”不能直接等于“把雾突然调浓”。雾的运动与形态是既定美术状态；调度器读取可见性，把合适的切换安排进去。

部分雾遮挡可以降低局部误差的可见性，但不意味着任意大错都能被隐藏。主峰轮廓至少应有可无遮挡连续观察的路段，以验证引擎本身而不是遮罩。

缺少新资产时的降级顺序：继续使用仍有效的旧景片，使用预先准备的低细节后备版本，在既定遮挡窗口交接。不得无限增强浓雾、产生破洞或卡住镜头等待慢速绘画。

## 10. 运行时状态

参考状态可用 REUSE → PREFETCH → READY → TRANSITION → REUSE 表示，另有 FALLBACK。PREFETCH 初版指加载已预生成资产；将来才考虑把未完成的绘画任务纳入其中。

转换权重应优先绑定路线位置和可见性，时间仅用于有界平滑。必须设置滞回，避免在边界来回走半步就频繁切换；停止和倒退应产生可预测的空间结果。

真实出现的新山脊、新后层或者旧景片画幅之外的区域，不能靠变形凭空补出。必须在承诺的观察域内提前准备可见内容。

## 11. 第一轮验证

用一段短路线包含直行、侧向经过、转弯、停步、倒退和转头。安排一座长期可见主峰、几组前后山及少量谷雾。极近景只保留接口，不为本次验证扩展完整植被、石块和路面系统。

阶段A：现有画迹 + 简单分层/起伏网格，不重画，验证山体视差和轮廓是否稳定。

阶段B：只为一个中景山体增加相邻视点版本，验证对齐、局部更新、笔迹尺度与切换；远景继续复用。

阶段C：加入沿游线的谷雾和过渡编排，比较有雾与无雾结果；避免用雾遮掉系统性错误。

阶段D：对整条约定观察域做自动回放检查，加入缓存、停止、倒退、资源延迟和视域边缘压力测试。

首轮验收关注：主峰无明显跳动，皴笔不游泳，留白不透后山，回头没有未覆盖区域，停步没有随机换画，倒退没有版本抖动，新版本切换没有双轮廓，雾不会随更新突变。

可先用1080p下主轮廓约1像素误差作为保守的调试起点，再按实际笔触宽度和观察实验修订；该数值不是人眼阈值或本项目已验证指标。任何性能帧率、参考视点数量、可行步长和资产体量必须以原型实测确定。

## 12. 不做的事情与后续边界

不重开笔触物理优化，不做逐帧生成，不先建设完整三维山水世界，不把普通实时三维滤镜作为主画面，不使用整屏淡入淡出掩盖结构跳动。

为未来近景保留相机变换、投影、深度/覆盖合成和雾透射接口；不预设其一定采用某一种投影手段。若将来做双目显示，两眼必须共享同一稳定场景表示并分别投影，不能独立生成左右眼水墨画。

项目判断：最值得先解决的是“同一座山在相邻游线区段还是同一座山”，然后才是铺设更多场景。画的生成可以慢，空间反馈必须连续。

## 技术依据

下列文献支持底层表示和时间一致性的选择，不代表本提案的水墨效果、阈值或性能已经由文献验证。

1. Wood 等，Multiperspective Panoramas for Cel Animation，SIGGRAPH 1997。沿预定相机路径组织多透视背景画。
   https://disneyanimation.com/publications/multiperspective-panoramas-for-cel-animation/
2. Shade 等，Layered Depth Images，SIGGRAPH 1998。带深度景片及多层图像表示。
   https://www.microsoft.com/en-us/research/publication/layered-depth-images/
3. Debevec 等，Efficient View-Dependent Image-Based Rendering with Projective Texture-Mapping，1998。用近似几何和稀疏视图进行投影及视点相关外观选择。
   https://www.pauldebevec.com/Research/VDTM/
4. Meier，Painterly Rendering for Animation，SIGGRAPH 1996。绘画动画中的笔迹附着与时间一致性。
   https://disneyanimation.com/publications/painterly-rendering-for-animation/
5. Praun 等，Real-time Hatching，SIGGRAPH 2001。预生成画迹在不同尺度和色调间的一致性。
   https://hhoppe.com/proj/hatching/
6. Burley 等，Dynamic Screen Space Textures for Coherent Stylization，SIGGRAPH 2024。水彩风格中屏幕纹理与运动一致性的问题。
   https://disneyanimation.com/publications/dynamic-screen-space-textures-for-coherent-stylization/
